## Problem

Two independent problems that were initially conflated.

**P1 — contract drift.** `octonomy-go` v0.1.0 targets Octonomy REST **v1** at server contract
**1.0.0** and implements **2 of 8** resource groups. The server is at **3.1.0** and has made
**`/api/v2` the primary advertised surface**, adding the namespace (merchant/sub-tenant) axis.
Nothing in the repo detected this drift, because no mechanism existed to detect it.

**P2 — a blocked consumer.** A real consuming team cannot compile the SDK on Go 1.13. The blockers
are **generics** (`pagination.go:37` `type List[T any]`, instantiated at `tags.go:131-132` and
`vocabularies.go:101-102`) **and the `any` alias at five independent sites** (`types.go:5`,
`errors.go:29`, `transport.go:33`, `transport.go:109`, `pagination.go:37`). Removing generics alone
does not fix it; a real `go1.13` compile reports 10 errors.

P1 and P2 have **opposite** requirements: P1 wants a modern, growing client; P2 wants a frozen,
old-toolchain client. Revision 1 of this plan tried to serve both with one Go floor. Revision 2
splits them, which is both cheaper and better.

## Vision

### 10x Check

The SDK today is an HTTP wrapper. Octonomy is an **event-sourced taxonomy service**: a transactional
outbox publishes 11 typed event types over HMAC-SHA256-signed webhooks, with a fully written consumer
contract in the server's `docs/events.md` (envelope, per-event payloads, entity snapshots,
at-least-once delivery, dedupe on `id`, correlation on `operation_id`, namespace-aware routing).

**There is no Go code for any of it.** The verification is security-critical and easy to get subtly
wrong: comparing digests with `==` instead of `hmac.Equal`, or parsing the body before verifying it.
A broken signature check still returns 200, so it fails permanently and silently.

*Honest caveat (found by the outside voice):* no Octonomy deployment currently emits webhooks.
`OUTBOX_TRANSPORT` defaults to `logging` (`config/settings.py:395`), `.env.example` and
`deploy/kubernetes/configmap.yaml` both set `logging`, and `deploy/.env.production.example` has the
webhook lines commented out. So E1 is a bet on a **written, stable contract**, not a response to a
named consumer. That is a materially weaker justification than rev 1 claimed, and it is the same
"no consumer has defined the semantics" objection used to defer E7 — applied to an item costing 4x
as much. It is still judged worth doing because the contract is fully specified and the security
cost of every consumer hand-rolling it later is high, but the justification is a bet, not a need.

### Platonic Ideal

A Go engineer adds tagging to a product catalog and has tags rendering in five minutes. They never
open the OpenAPI spec. They never write an offset loop. A 409 tells them whether it was a duplicate
slug or an illegal scope change, and the doc comment says what to do about it. Mid-rollout flag
states read as `namespaced writes are disabled on this deployment`, not `403 forbidden`. One request
ID they supply appears in Octonomy's audit log, the emitted webhook event, and the server's logs.
When the taxonomy changes, their webhook handler knows in seconds and the signature check was
already correct.

**One line: the SDK never makes you think about Octonomy's internals, and never lets you be silently
wrong.**

## Architecture Decision: two module paths (semantic import versioning)

The SDK ships **two module paths**. Go treats them as different modules, so version selection
cannot cross between them:

```
  github.com/octoverse-id/octonomy-go          v1.x    branch: support/go1.13
      Go 1.13. NO generics. Vocabularies + Tags. /api/v1 only.
      FROZEN: security fixes only. Sunset published.

  github.com/octoverse-id/octonomy-go/v2       v2.x    branch: main
      Go 1.24+. KEEPS generics. All 8 resources. v1 + v2 + namespaces.
      Webhooks, integration tests, drift gate, examples.
      Versioned v2.0.0-alpha.N until API freeze.
```

**Go enforces this.** A tag whose `go.mod` declares a different path is rejected at resolution —
verified against the proxy:

```
go: github.com/google/go-github@v50.0.0: invalid version:
    go.mod has post-v50 module path "github.com/google/go-github/v50" at revision v50.0.0
```

So no transitive dependency, `go get -u`, or Dependabot bump can move a Go 1.13 consumer onto code
they cannot compile. **No build-tag tripwire and no consumer-side pin are needed** — earlier
revisions of this plan required both because they used a version-range split on one path, which Go
does **not** enforce (minimal version selection treats `require` as a floor, and pre-1.16 Go
auto-resolves `@latest` on a first build). See the Engineering Review section for the full history.

**Why the split at all:** the two problems have opposite requirements. Keeping generics on the modern
line also dissolves two findings raised independently by two reviewers against rev 1 — `Each[T]` is a
single tested abstraction rather than N per-resource walkers, and `DecodeMetadata[T]` can be a generic
**function** instead of an impossible method on the `Metadata` type *alias* (`types.go:5` is
`type Metadata = map[string]any`; aliases cannot have methods).

## Corrections from Revision 1

Rev 1 contained three factual errors and eight underspecifications. All were found by adversarial
review plus an independent Codex pass, and all were then verified directly against the repos. Ten
findings were raised **independently by both reviewers**, which is why rev 2 treats them as settled
rather than debatable.

**Correction 1 — the `scope` query param is NOT on the tag list.** Rev 1 said S3 should add `scope`
to `TagListParams`. Verified false: `awk` over both specs shows `name: scope` appears exactly once
per spec, under `/api/v1/tag-resolution` (line 429) and `/api/v2/tag-resolution` (line 863). The
tags list has zero occurrences and is byte-identical to the SDK's vendored copy. **`scope` belongs
to `Tags.Resolve` in S6.**

**Correction 2 — five documents assert facts this plan invalidates.** `AGENTS.md:39` mandates
"Target Go **1.24+**", `AGENTS.md:5` mandates "the stable REST **v1** API", `AGENTS.md:29` mandates
"List methods return `*List[T]`". `README.md:21` says "Requires Go 1.24 or newer." `doc.go` says
"targets the stable v1 API (server release 1.0.0)". `docs/versioning.md` pins "currently **v1**,
server `1.0.0`" **and states a server major "would be tracked by a corresponding major SDK effort"**
— which directly contradicts shipping v2 in a 0.3.0 minor. `docs/roadmap.md` documents
`Tags.Resolve` with the wrong parameter set. `AGENTS.md` is the agent instruction file this plan
cites as authority twice, so leaving it false actively misdirects future work.

**Correction 3 — "an unrecognized 409 is a silent failure" is false.** `parseError`
(`transport.go:101-125`) already preserves whatever `code` string the server sends, so
`scope_immutable` is *already* visible as `apiErr.Code`. What is missing is a named constant and an
`Is*` helper: convenience, not silence. This retracts rev 1's stated rationale for putting the
contract refresh in the unblock release.

**Correction 4 — REST models and event snapshots are different contracts.** `docs/events.md`
specifies snapshots that **omit** `usage_count`, `namespace_type`, and `namespace_id` — all three of
which the v2 REST `Tag` carries and lists as `required`. Worse, `*.updated` payloads "contain only
the fields that actually changed", so reusing `octonomy.Tag` for `before`/`after` yields zero values
indistinguishable from real ones. **S18 (the deferred issue) must define distinct snapshot types with pointer fields**,
reusing only `Metadata` and the enum constants. Rev 1's "read path and event path share one set of
types" was wrong. Also: `X-Octonomy-Request-ID` is emitted conditionally (`if event.request_id`),
unlike the other four webhook headers.

**Correction 5 — `X-Request-ID` needed no API redesign after all.** Both reviewers correctly noted
that `do()` discards `resp.Header` and every method returns `(*T, error)`, so there is nowhere to
surface a server-minted ID without changing every signature, adding a callback, or introducing
non-concurrency-safe client state. The resolution is simpler than any of those: **if the caller
supplies the ID, they already have it.** E2 ships the send side only, and the documented guidance is
that callers generate their own. No success-path surfacing, no signature changes.

**Correction 6 — the container image is not an integration harness.** `docker-compose.yml` shows it
needs Postgres 16 behind a healthcheck, `DJANGO_SECRET_KEY`, `SERVICE_TOKEN_PEPPER`, and
`ALLOWED_HOSTS`. The entrypoint runs `manage.py check` but **not** migrations. Auth needs a token
minted via `create_service_token`. Critically, `config/settings.py:393` sets
`NAMESPACE_WRITE_ENABLED` default **false**, so any namespaced-write test returns
`403 namespaced_writes_disabled` unless `OCTONOMY_NAMESPACE_WRITE_ENABLED=true` is set. E3 doubles
to ~3 h; E8 does not become cheap merely because E3 pulls an image.

**Correction 7 — a path-to-method inventory is coverage tracking, not drift detection.** It would
not have caught the drift this plan exists to fix (query params, schemas, error codes, response
envelopes). The server's own gate regenerates its **own** spec in-repo and `git diff --exit-code`s
it; the SDK's gate must reach across repos, so it *adapts* that pattern rather than mirroring it.

**Correction 8 — `t.Cleanup` → `defer` is not a valid mechanical swap.** The sole use is
`octonomy_test.go:15-16`, inside helper `newTestClient(t, handler) *Client`, which then **returns**.
`defer srv.Close()` there closes the server before any test runs, breaking all 14 call sites. S1
must change the signature to `newTestClient(t, handler) (*Client, func())` with `defer cleanup()`
at each call site.

**Correction 9 — `Metadata` cannot have methods.** `types.go:5` is `type Metadata = map[string]any`,
a type **alias**. `DecodeMetadata` must be a generic function; converting `Metadata` to a defined
type would itself be a breaking change.

**Correction 10 — health probes are unreachable.** `New()` rejects a blank `Token` or `TenantID`
(`octonomy.go:59-67`), so a caller cannot construct a client to reach the unauthenticated
`/health/live`. An auth-skipping transport method does not solve this; S10 needs a separate
constructor.

**Correction 11 — `roadmap.md` is a drifted artifact.** S5-S9 must not delegate to it until it is
re-derived from `openapi-v2.yaml`. That re-derivation is a prerequisite deliverable of S4.

**Correction 12 — arithmetic and precision.** Rev 1's item figures summed to 9.5 h while its stage
figures summed to 9.0 h. Also: "92 diff lines" was the `diff -u` output length; the substantive v1
change is **50 added lines plus one version bump**, which understates nothing but oversells the
movement. And `application_id` is documented as **required for namespaced requests**, a second
config-coherence guard opportunity.

### Compat line (`support/go1.13` line, `v1.x`)
- Remove generics: `List[T]` → `TagList`, `VocabularyList`
- `any` → `interface{}` at all five sites, plus every test file
- `io.ReadAll` → `ioutil.ReadAll` at **all five** sites — 1 in the library, **4 in test files**
  (verified: emits no lint noise at `go 1.13`)
- **The go1.13 CI job must run `go test`, not only `go build ./...`.** Four of the five `io.ReadAll`
  sites and all 18 test-file `any` occurrences live in `_test.go` files, which a build-only job never
  compiles. A build-only gate would pass green while the compat line's tests could not run at all on
  the toolchain the line exists for
- `newTestClient` returns `(*Client, func())`; `defer cleanup()` at all 14 call sites
- `go.mod`: `go 1.24` → `go 1.13`
- CI: **a real go1.13 job (required check)** + keep modern jobs for lint/vuln
- CI: **mistag guard, split by severity** (Correction 32 + eng review 5bA). The **blocking** half
  gates the **release PR** and asserts that on `support/go1.13` the `go.mod` still declares
  `go 1.13` — that assertion has no toolchain backstop. The path/branch half is **advisory only**,
  because Go rejects a module-path mismatch itself. A tag-time-only check is too late: it fires after
  the tag is already proxy-resolvable, and `retract` is inert for this audience
- Scope frozen at Vocabularies + Tags, `/api/v1` only. No v2, no namespaces, no webhooks, ever.

### Modern line (`main`, module path `/v2`, `v2.x`)
- Keep generics, `io.ReadAll`, `t.Cleanup`. Go 1.24+.
- `Config.APIVersion` — **default v2** (see R9; user decision, risk accepted and documented)
- Namespace scoping: **per-request only, no `Config` field** (Threat 3.5 mitigation). Atomic
  type+id pair. `WithNamespace(type, id)`, `WithGlobalNamespace()`
- **`include_global` is a QUERY parameter, not a header** (Correction 19), owned by S4 rather than left
  implicit. `RequestOption` feeds only headers today and `do()` receives `query` pre-built by the
  resource method, so this needs new plumbing. It is also **meaningless on writes**, so it must live on
  read `*ListParams` or error loudly when applied to a write — a silent no-op is not acceptable
- **Client-side config-coherence guard** (rules corrected per Correction 20: the reserved-`global`
  prohibition applies to the **`X-Namespace-Type` header only**; `scope=global` is a **legal** explicit
  pin on `/tag-resolution` and must NOT be rejected; `scope` is an **enum** `global`|`merchant` though
  the spec types it as a bare string; and the missing converse rule — **`scope=merchant` requires a
  namespaced request** — is now included) for namespace-on-v1, blank id, type-without-id, reserved
  `global`, and missing `application_id` on a namespaced request. Narrowly scoped to configuration
  coherence, **with an explicit exemption added to `AGENTS.md`** so it is not later reverted as a
  violation of "do not encode server-side validation"
- **Namespace fields on response models — SEVEN schemas** (Correction 16): `Tag`, `Vocabulary`,
  `TagAlias`, `TagResource`, `Assignment`, `AuditLog`, `ResourceTag`. Six mark them `required`
- Six new error codes + `Is*` helpers, each with a doc comment naming the **operator** remediation
- Three **pre-existing** gaps closed: `Is*` helpers for `tenant_mismatch`,
  `application_mismatch`, `inactive_tag` (constants exist at `errors.go:18-20`; helpers do not, and
  the latter two are exactly what assignment writes raise)
- **One `codeFromStatus` rule, stated once (Correction 29).** Rev 3 said both "an envelope-less
  non-2xx must not map to a semantic code" and "add a 5xx fallback so a 503-with-envelope is
  distinguishable" — which read as opposites. They reconcile under a single rule: **any non-2xx
  arriving WITHOUT the Octonomy error envelope gets one distinct non-semantic code** (e.g.
  `CodeUnexpectedStatus`), never `not_found`/`conflict`/etc. A 503 *with* an envelope keeps its real
  `namespace_api_disabled`, so the two 503s stay distinguishable — the 5xx bullet's actual intent —
  and an unrouted 404 stops satisfying `IsNotFound`. `errors.go:73-88` returns `""` for 5xx and a
  semantic code for 400/401/403/404/409; **both halves change**
- **This changes behaviour for existing v1 callers** who rely on `IsNotFound` for a bare 404. It needs
  its own CHANGELOG entry, not a mention buried in the v2 notes
- Six new resource groups: tag aliases, tag resolution (with `scope`), tag assignments (+bulk),
  resource tags, audit logs, health (separate constructor)
- E1, E2, E3, E4, E5, E6, E8, S12
- Extract header assembly out of `do()` — it exceeds the 5-branch complexity threshold once
  version, namespace, and request-ID land
- Document that webhook callers must bound the body themselves with `http.MaxBytesReader` before
  calling `Verify`. Doing it *for* them is a `Handler` concern and moved to the deferred issue with the
  handler (Correction 24)
- Document the `http.RoundTripper` extension point for caller-side metrics and tracing
- Document `http.DefaultTransport`'s `MaxIdleConnsPerHost: 2` as the first scaling bottleneck

## NOT in scope

- **E7 tag tree helper** — deferred. Needs consumer-defined orphan/cycle semantics.
- **Generated client from OpenAPI** (`oapi-codegen`) — eliminated. Needs Go 1.20+ and a runtime
  dependency, breaking the dependency-free rule. The vendored spec also documents list responses as
  bare arrays while the server returns `{data, pagination}`, so generation would be wrong on every
  list endpoint.
- **Client-side HTTP response caching** — investigated and dropped. Server sets `Vary` via
  `patch_vary_headers` but emits **no** `ETag` or `Cache-Control`.
- **Retry / backoff in the client** — `AGENTS.md` reserves this for the caller's `*http.Client`.
- **Any v2, namespace, or webhook support on the compat line** — explicitly excluded by T1c policy.
- **Shared transport extraction for future SDKs** (python, ts) — separate scope. A shared
  *signature test-vector fixture set* across SDKs is the piece worth recording for later.

## Compat line support policy (write into `docs/versioning.md`)

- `v1.x` receives **security fixes only**. No features, no bug fixes, no v2, no namespaces, no
  webhooks.
- A **published sunset date** after which `v1.x` receives nothing. Gives the blocked team a date
  to plan their toolchain upgrade against, which is the only real fix.
- **`retract` is inert for this audience.** Verified: `retract` parses under `go 1.13` on a modern
  toolchain, but the directive shipped in Go 1.16, so a Go 1.13 consumer's toolchain will not honor
  it. A published `v1.x` cannot be recalled for the people it exists to serve. **v1.0.0 must be
  right the first time** — which is why the go1.13 CI job is a required check and why v1.0.0 contains
  exactly one change.

## Key API decisions (resolved — do not re-litigate)

1. **List type naming (compat line):** `TagList`, `VocabularyList`. `Pagination` and `ListOptions`
   stay shared and unchanged. Modern line keeps `List[T]`.
2. **`APIVersion` default:** **v2.** User decision against both reviewers' recommendation. Risk R9

3. **Namespace:** per-request only, no `Config` field. Atomic type+id pair.
4. **Namespace guard:** client-side, narrowly scoped to config coherence, with an `AGENTS.md`

10. **`DecodeMetadata`:** a generic function, not a method. `Metadata` is an alias.

Established by reading both repos and running probes. Independently reproduced by the adversarial

1. **Language version IS enforced; stdlib version is NOT.** With `go 1.13` in `go.mod`, Go 1.25

## Architecture change: semantic import versioning replaces the version-range split

```
github.com/octoverse-id/octonomy-go        compat line   v1.x   Go 1.13   FROZEN
github.com/octoverse-id/octonomy-go/v2     modern line   v2.x   Go 1.24+  keeps generics
    └── /v2/webhook
```

Go treats these as **different modules**, so version selection, `go get -u`, and Dependabot cannot
cross between them. Verified against the proxy:

```
go: github.com/google/go-github@v50.0.0: invalid version:
```

## Mandated regression test (IRON RULE — not optional)

`octonomy_test.go:194-211` is the only envelope-less test. It uses a **502** and asserts `StatusCode`
and `Message` but **never `Code`** — which is how the 404 trap went unnoticed. There is no
envelope-less 404 test at all. Required: envelope-less 404 → `IsNotFound` **false**; envelope-ed 404
→ **true**; envelope-less 503 distinguishable from an envelope-ed `503 namespace_api_disabled`; and
extend the existing test to assert `Code`.

## Two things nobody had noticed

- **`ci.yml` triggers only on `main`**, so the compat branch would have had zero CI. And the `go1.13`
  job must run **`go test`**, not just `go build ./...` — four of the five `io.ReadAll` sites and all
  18 test-file `any` occurrences live in `_test.go`, which a build-only job never compiles.
- **The originally planned `compat/go1.13` was an invalid branch name** — `compat` is not an allowed
  type under `AGENTS.md:68`. Resolved by adding a **`support/<description>`** category to `AGENTS.md`
  for long-lived maintenance lines, explicitly exempt from the issue-number rule because such a line
  closes no issue. The three branch roles are now distinct and each checkable against a written rule:
  **`support/go1.13`** is the line, **`chore/<issue>-<desc>`** implements work onto it, and
  **`release/vX.Y.Z`** cuts the tag (`AGENTS.md:89`).
