## Problem, restated

The request was "the v1 line does not support Octonomy API v2; make it, so the only difference
between the SDK lines is the Go version." The audit found the premise inverted.

Both vendored contracts publish the **same 18 paths**. `/api/v2` adds the namespace axis and
nothing else. The real gap is that `support/go1.13` implements **2 of 8 resource groups**.

| | `support/go1.13` (v1) | `main` (v2) |
| --- | --- | --- |
| Non-test SDK Go | **850** | **6,616** (5,044 excl. webhook) |
| Tests | **844** | **18,170** (15,529 excl. webhook) |
| Resource groups | 2 of 8 | 8 of 8 |
| REST surfaces | `/api/v1` only (`apiPrefix` is a `const`) | v1 + v2 via `Config.APIVersion` |
| Namespace axis | none | 4 scope options + `checkScopeCoherence` |
| PATCH semantics | `*T` + `omitempty` (cannot clear) | `Optional[T]` + `omitzero` |
| Silent-zero guards | `decodeEnvelope` only | + `identityFields()` / `requireIdentity` |
| Response size bound | **none** | 32 MiB + `ErrResponseTooLarge` |
| Vendored contract | `openapi.yaml` at `info.version: 1.0.0` | both specs at 3.2.1 + coverage rows + gate |
| webhook | none | 1,572 lines + portable vectors |

### The stated goal is not literally reachable, and that is a fact about Go

Go 1.13 has no type parameters and no `omitzero` (Go 1.24; `optional.go:63-64` says so). So
`octonomy.Set("x")` becomes `octonomy.SetString("x")`, `*List[Tag]` becomes `*TagList`, and every
`*Update` needs a generated `MarshalJSON`. **Capabilities can reach parity. API shape cannot.**
This plan targets capability parity and makes the shape delta a committed, checkable artifact
(`COMPAT.md`, per F10).

### Four live defects found on the frozen line

1. **`codeFromStatus`** (`support/go1.13:errors.go:73`, `transport.go:229`) maps a bare 404 to
   `CodeNotFound`, so `IsNotFound(err)` returns true for a wrong `BaseURL` or a misrouted proxy.
   `main` deleted it in #7 and its CHANGELOG (`:974`) calls the removal a behavior change for v1
   callers. Adding `/api/v2` without addressing it reproduces #7 on a line `retract` cannot reach.
2. **`identityFields()` is absent**, so #40 is live: `{"data": {"id": null}}` or a renamed id
   decodes to a zero-valued resource with a nil error. Multiplies by eight with D3.2.
3. **No response-size bound.** `ioutil.ReadAll(resp.Body)` is unbounded.
4. **The vendored contract is `info.version: 1.0.0`** — two server majors stale, with no
   `openapi-v2.yaml`, no `contract-coverage.yaml`, no `tools/`, no contract-version marker.

### Prior decision being reversed, deliberately

`gstack-decision-search` holds this from 2026-08-19: *"P1 (contract drift, wants a growing modern
client) and P2 (a consumer blocked on Go 1.13, wants a frozen old-toolchain client) have opposite
requirements."* The freeze is that decision's conclusion, not an oversight. Reversed with the
owner's explicit call; new decision logged as `36fac864`.

## Vision — the 10x

The compat line stops being a branch somebody remembers to update and becomes a build output.
`sibling-branch-fixes-do-not-propagate` is a recorded learning on this repo, earned by shipping a
broken transport on one line while the other was correct. With the sunset held at 2027-08-31, the
generator's justification is **translation correctness on an unrecallable line**, not maintenance
savings: hand-translating 5,000 lines into a release that cannot be withdrawn is precisely where a
silent bug ships forever.

**Two rules are load-bearing against silent failure.** The loop shadow: a mechanical rewrite
without `i := i` makes every goroutine read the final `i`, turning `scope_test.go`'s concurrency
test into a no-op that still passes. Multi-`%w`: **pre-Go-1.20 `fmt.Errorf` with two `%w` verbs
produces no `Unwrap` at all**, so `errors.Is(err, ErrUnreachable)` returns false — a documented
guarantee broken silently, and `go vet`'s duplicate-`%w` check postdates 1.13.

## Revision 3 — outside voice (Codex), 2026-09-23

Codex ran after the sections and the first adversarial pass, found seven issues, and recommended
**pausing the epic**. Five claims were checkable; all five hold. Two changed the plan's foundations.

### C1 — the plan contained a source-breaking change nobody caught in two passes

`support/go1.13:tags.go`'s `TagUpdate` is `*string`/`*bool`/`Metadata` + `omitempty`, and `types.go`
exports `String()`, `Bool()`, `Int()`. A published caller writes `TagUpdate{IsActive: Bool(false)}` —
the compat tests contain that expression. Porting `Optional[T]` **breaks their build**, and this line
can never publish a major.

**Decision (C1-A): the pointer fields stay.** The transform rule becomes `Optional[string]` →
`*string` + `omitempty`, reproducing the existing shape exactly. `optional_compat.go`,
`marshalOptionalStruct` and the three `Optional*` types leave scope; **#96 is closed**; ~6 days come
out. `v1.1.0` is a clean MINOR with no source break.

**Named carve-out:** the compat line cannot CLEAR a nullable field. #64 stays live there for
`TagUpdate.ParentID`, `.VocabularyID`, `.Description` and `VocabularyUpdate.Description`.

**And the half nobody had decided at all:** `Config.APIVersion` defaults to **`APIV1`** on the compat
line, not `APIV2` as `main` does. Copying main's default would silently move every existing caller's
requests to a different surface on an in-range upgrade.

### C2 — the corrected multi-`%w` rule was still wrong

`%w` + `%v` preserves the sentinel **or** the cause, never both. `health_test.go:188` asserts both,
with the comment *"the cause must survive the wrap so a caller can tell a cancellation from a refused
connection."* Fix: a Go 1.13 wrapper type with `Unwrap()` for the cause and `Is()` for the sentinel.

### C5/C7 — strategic, and the reason Codex said pause

The generator does not cover Zone 1: ~1,900 hand-maintained lines holding transport, scope
enforcement, decoding and error handling. A behavioral fix there can leave exported symbols unchanged
and every generated resource compiling, so neither `COMPAT.md` nor a successful transform detects the
divergence. **The generator does not solve sibling-branch drift where drift is most dangerous.**

**Decision (C2-A): proceed, with an entry criterion.** #89 is blocked until the consuming team
answers which calls block adoption, whether they need namespaces at all, and whether they can
validate a replacement before 2027-08-31. Plus a cross-implementation behavior vector file both lines
run against, so a Zone 1 fix applied to one line and not the other fails on the line that missed it.

### Corrections folded without a decision

- `readProbes` is in `integration_suite_test.go`, not `integration_harness_test.go`.
- `ci.yml:246` runs `-run TestSmoke_RealServer`, so a ported isolation test would never execute. A

- `t.Cleanup` inside a helper runs at the **test's** end; a helper-local `defer` runs at the

### Probe that settled Issue 3

Run against a real `go1.13.15` (the `GO113` default; see `support/go1.13:docs/development.md` for
how to fetch one, or `GO113=<path> make test-go113`):

```
  *string + json:"description,omitzero"   nil ->  {"name":"renamed","description":null}   WRONG
  *string + json:"description,omitempty"  nil ->  {"name":"renamed"}                      correct
  same source on go1.25.4:                nil ->  {"name":"renamed"}   (both look fine)
```

Go 1.13's `encoding/json` parses `omitzero` as an option and matches nothing, so the field is
always emitted. #96 was closed on the reasoning that "with pointer fields and `omitempty` there is
